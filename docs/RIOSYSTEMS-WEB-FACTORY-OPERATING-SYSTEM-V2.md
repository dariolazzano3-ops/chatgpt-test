# RIOSYSTEMS Web Factory Operating System V2

## Purpose

Web OS V2 is the intelligence layer above the existing Web Factory V1 and Autonomous Premium Web Intelligence stack. It does not replace the native builder, Framer bridge, fidelity engine, QA, repair, deployment artifacts or existing provider routing.

The lifecycle is:

`Business intent -> compiler -> strategy -> information architecture -> journeys -> page intent -> brand/design intent -> content/component composition -> native/premium build -> SEO/accessibility/performance/visual/CRO/security QA -> bounded self-healing -> cross-factory contracts -> versioning/regression/deployment contracts -> delivery manifest`.

## Core principles

- RIOSYSTEMS owns strategy, design intent, structure, QA, repair policy and delivery contracts.
- Providers perform specialist roles and remain replaceable.
- Native Builder is the default production motor for portable code artifacts.
- Framer is an optional premium visual specialist, not the default host.
- Webflow is a complex CMS specialist candidate.
- Lovable is a rapid prototyping specialist candidate.
- Cloudflare remains the preferred hosting candidate for owned native artifacts.
- No provider is automatically paid or activated.
- No production deployment, DNS or custom domain action is performed by Web OS V2.

## New V2 layers

### Natural-language compiler and strategy

Deterministic compiler contracts translate a natural-language request plus explicit context into a provider-neutral website mission. Website strategy, reusable industry recipes, information architecture, user journeys and page intent contracts are then generated before any build stage.

### Brand, design system, components and content

Brand inputs are converted into a provider-neutral website direction. Web OS V2 generates reproducible design tokens, typography/layout contracts, canonical components and variants, structured page content plans, AI Factory content requests, brand voice checks, content consistency checks, trust plans and form contracts.

Content generation remains an AI Factory responsibility. Web Factory only creates and validates the structured handoff.

### SEO, localization, responsive, accessibility and performance

V2 adds structured SEO architecture, technical SEO QA, Local SEO, structured-data intent, guarded programmatic SEO, DE/EN/FR/IT-ready localization and hreflang mappings. Responsive and accessibility models have bounded safe repair loops. Performance QA uses declared or artifact-derived measurements only and never claims Lighthouse or browser measurements that were not executed.

### Lifecycle governance

V2 models CMS necessity, provider capabilities, cost governance, advanced interactions, migration/redirect safety, website/build versioning, change impact, blast radius, visual/content/technical regression contracts, rollback, preview/deployment contracts, security headers, form security, third-party scripts, consent, analytics quality, PostHog experiment handoff and future learning contracts.

### General self-healing

Repair priority is fixed as:

1. blocking technical
2. security
3. accessibility
4. broken responsive
5. SEO
6. CRO
7. visual polish

Repairs are bounded, deterministic where possible, recorded with before/after state and fail closed when unresolved.

### Cross-factory contracts

Web OS V2 emits correlation-scoped contracts for Business Factory, Automation Factory, AI Factory and analytics. It never performs those factories' domain mutations itself.

Standard website events include `page_view`, `cta_clicked`, `form_started`, `form_submitted`, `lead_created_request`, `booking_clicked`, `phone_clicked`, `email_clicked`, `download_clicked` and `pricing_viewed`. Analytics payloads are privacy-minimized and raw form payloads are excluded.

## Quality claims

The Web Quality Score is derived only from explicit gates: build, responsive, SEO, accessibility, performance, visual, CRO, integration and rights. It is not an arbitrary AI score.

Screenshot/pixel fidelity is only claimed when a screenshot runtime actually ran. Otherwise screenshot comparison remains explicitly unexecuted. High-fidelity mode may therefore fail closed when screenshot evidence is required.
