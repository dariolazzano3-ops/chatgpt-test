# RIOSYSTEMS Web Factory — Autonomous Premium Web Intelligence V1

## Purpose

This extension turns the existing Web Factory into one coherent autonomous premium website production pipeline without replacing Web Factory V1 or the Framer / Visual Fidelity bridge.

Pipeline:

MISSION + BRAND + VISUAL REFERENCES + OPTIONAL COMPETITOR EVIDENCE + BUSINESS REQUIREMENTS
→ WEBSITE STRATEGY
→ MULTI-REFERENCE FUSION
→ DESIGN INTENT
→ PROVIDER-NEUTRAL DESIGN CONTRACT
→ OWNED NATIVE RECONSTRUCTION
→ VISUAL FIDELITY QA
→ VISUAL QUALITY DIRECTOR
→ CRO QA
→ TECHNICAL QA
→ BOUNDED REPAIR
→ BUSINESS INTEGRATION HOOKS
→ DEPLOYMENT-READY ARTIFACT
→ DELIVERY MANIFEST

## Core contracts

- `riosystems.web-mission.v1` extended with visual references, competitor references, operator design intent, motion, localization, migration input, integration requirements and provider preferences.
- `riosystems.screenshot-to-design-spec.v1` defines structured screenshot/reference attributes. No property is marked observed unless structured evidence or a verified vision adapter supplied it.
- `riosystems.multi-reference-fusion.v1` combines references using operator instruction > explicit reference priority > brand rules > reference defaults.
- `riosystems.web-design-intent.v1` creates one coherent design direction rather than a collage.
- `riosystems.visual-quality-director.v1` separates deterministically verifiable checks from subjective screenshot/human review.
- `riosystems.web-cro-review.v1` checks conversion structure without dark patterns.
- `riosystems.motion-design-contract.v1` requires purpose and reduced-motion fallback.
- `riosystems.web-localization.v1` supports localized slugs/metadata/hreflang readiness and never changes currency automatically.
- `riosystems.web-migration-plan.v1` inventories supplied migration data and never reuses uncertain assets automatically.
- `riosystems.web-business-integration-plan.v1` emits hooks only. Business Factory, Automation Factory, AI Factory, Supabase, Make and PostHog retain their own execution/domain logic.
- `riosystems.web-experiment-contract.v1` is architecture only and cannot switch production automatically.
- `riosystems.web-delivery-manifest.v2` aggregates strategy, intent, references, competition, industry, design, motion, localization, QA, CRO, integrations, routing, cost and safety evidence.

## Screenshot truthfulness

The repository has a screenshot-comparison contract and adapter. The zero-cost CI environment currently does not render/reference screenshots through a browser/image runtime, therefore reports must explicitly say `NOT_EXECUTED_RUNTIME_UNAVAILABLE`. Structured fidelity is measured separately and must never be described as pixel similarity.

`HIGH_FIDELITY` requires actual screenshot evidence and fails closed without it.

## Rights and originality

Reference elements are classified as generic principles or rights-sensitive material. Logo, photography, illustration, copy, paid assets, custom icons and proprietary components with unclear rights become `REPLACEMENT_REQUIRED`.

High visual fidelity never overrides rights safety. Raw provider HTML and proprietary component extraction remain forbidden.

## Standard privacy-safe website events

`page_view`, `cta_clicked`, `form_started`, `form_submitted`, `lead_created_request`, `booking_clicked`, `phone_clicked`, `email_clicked`, `download_clicked`.

Analytics hooks exclude raw form payloads by default.

## Quality levels

- STANDARD: structured fidelity target 85, up to 2 visual repair attempts.
- PREMIUM: structured fidelity target 93, up to 3 visual repair attempts.
- HIGH_FIDELITY: structured fidelity target 97, up to 4 repair attempts and real screenshot evidence required.

These thresholds apply only to measurable structured fidelity properties. No 100% pixel-equality promise exists.
