# Track 11 | Launch, Produktqualität & Freigabe
**Mission:** Ein nachweisbar funktionierendes, verkaufsfähiges Lunara-Produkt ausliefern. Keine Prozentwerte ohne messbare Evidenz.

## G0 | Private Grundlage (teilweise erfüllt)
- [x] Originale Lunara-Factory und originale Mia-Designreferenz vorhanden.
- [x] Privater Story Builder mit iPad-Leseansicht, Original-Mia-Demo verfügbar.
- [x] Synthetischer Make-Lauf: Story → QA → Text-PDF → privates R2 erfolgreich.
- [x] Premium-Mia-PDF mit lokaler Make-Adapter-Designprobe erfolgreich geprüft.
- [ ] Offene Integrationsänderungen im autorisierten privaten Umfeld sicher deployen und dokumentieren.

## G1 | Synthetischer technischer End-to-End-Test (NICHT ERFÜLLT)
- [ ] Stripe-Testevent mit gültiger Signatur → korrekter D1-Status paid; ungültige Events werden abgewiesen.
- [ ] Ein bezahlter Testauftrag erlaubt maximal eine Make-Produktion; Duplikate erzeugen keine Kosten.
- [ ] Originale KI-Stufen plus QA-Fail → Reparatur → zweite QA korrekt.
- [ ] Premium-PDF aus **neu** generierter Geschichte automatisch gerendert und im privaten R2 gespeichert.
- [ ] Berechtigter Download, synthetische E-Mail-Zustellung, negative Zugriffs-/Timeout-/Wiederholungstests, Löschung.
- [ ] Eigene Geschichte nicht als fremde „neueste Story“ sichtbar. Gesonderter Kundenzugriff.

## G2 | Verkaufsbereitschaft (NICHT ERFÜLLT)
- [ ] Produktversprechen, Lieferumfang und Preis entschieden (01).
- [ ] Verkaufsstarke mobile Website, verständlicher Story Builder, echte Demo, Checkout und Bestätigung getestet (02/03).
- [ ] Pflichtinformationen, Datenschutz, Zugriffs- und Supportprozesse abgenommen (07/10).
- [ ] Messbarer, datensparsamer Funnel und tatsächliche Kosten pro Auftrag (09).
- [ ] Marketing-Bibliothek, kreative Beispiele und Kanalstartplan vorbereitet, noch keine Paid-Kampagne (08).

## G3 | Kleiner echter Pilot (NUR nach ausdrücklichem GO)
- [ ] Wenige echte freigegebene Bestellungen, echte Geldbewegungen, korrekte Lieferung und überprüfter Support.
- [ ] Kundenerfahrung, Preis, Retention, Conversion, Fehlerrate und Deckungsbeitrag messen; Probleme vor Skalierung beseitigen.

## G4 | Wachstum (SPÄTER)
- [ ] Marketingausgaben nur bei nachgewiesenem CAC/Deckungsbeitrag und zuverlässiger Lieferquote.
- [ ] Audio, native App, PWA, Hardcover, Abo nur mit eigenem Nachfrage- und Wirtschaftlichkeitsnachweis.

## Verbindliche Abnahme je Arbeitspaket
**Ziel / Scope / System / Commit / Nachweis / Kosten / Security / Rollback / Nächster Blocker**. Nur `DONE-VERIFIED`, `PARTIAL`, `BLOCKED`, `NOT-STARTED`, `DEFERRED`. Keine Liveschaltung, DNS-Änderung, echten Daten oder kostenauslösenden Aktionen ohne passende explizite Freigabe.

## Wichtig
Die originalen 90 Make-Module bleiben Referenz. Die private Vorschau bleibt geschützt. Ein einzelner bestandener lokaler Render-Test oder Stripe-Test-Checkout ist **kein** erfolgreicher Gesamtlaunch.
